Group retry acceptance: `npm run db:verify:group-retry` requires one existing verified allowlisted identity. It uses two connections and rolls both transactions back, proving a duplicate request waits for the first uncommitted request, continues after rollback, and reuses its own result on retry. It leaves no test business data. Run during a quiet period because verification compares row counts. It does not replace the other required races (collector claim, final invite use, poll closure, double approval and payment versus recalculation). CI now includes production build after typecheck/lint/tests; the remote workflow run and live production deployment remain unverified.
